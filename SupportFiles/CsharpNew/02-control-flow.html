These are the foundations of every real application—from login checks to menus.

Control Flow Mental Model (Decision + Repetition)

Control flow is the “path” your program takes while running. It is mainly two actions: decision (choose a branch using conditions) and repetition (repeat steps using loops). Almost every feature—login checks, price calculations, menus—uses control flow. The key skill is to make logic predictable: one clear condition, one clear outcome, repeated safely when needed. 

Program Flow
  Start
   |
   v
[Decision?] --yes--> Do A
   |                |
   no               v
   v             Continue
  Do B              |
   |                v
   +-------> [Repeat?] --yes--> loop back
                     |
                     no
                     v
                    End
Example: Real-world control flow

If password is correct → login success, else → show error. While user is not logged in → keep asking for credentials.

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        Console.Write("Enter PIN: ");
        string pin = Console.ReadLine();

        if (pin == "1234")
            Console.WriteLine("Access granted");
        else
            Console.WriteLine("Access denied");
    }
}
Tip: Write the logic in plain English first (“If X then Y else Z”), then code it.
Advanced note: Keep conditions small and readable; complex business rules are easier to test when split into well-named boolean variables.

Boolean Logic & Comparisons (==, !=, >, <, &&, ||, !)

Conditions evaluate to true or false. Comparisons like >, <, ==, != produce booleans, then logical operators combine them. Use && when both conditions must be true, || when either can be true, and ! to invert. Clean boolean logic prevents bugs like wrong eligibility checks or broken validations. 

Truth mini-map
  A && B  -> true only if both true
  A || B  -> true if at least one true
  !A      -> flips true/false

Example:
  age >= 18 && hasId == true  => eligible
Example: Eligibility check (real-world)

Allow entry if age ≥ 18 AND user has valid ID.

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int age = 20;
        bool hasId = true;

        bool eligible = (age >= 18) && hasId;
        Console.WriteLine("Eligible? " + eligible);

        bool blocked = !eligible;
        Console.WriteLine("Blocked? " + blocked);
    }
}
Tip: Use parentheses for readability even when not required—future you will read faster.
Advanced note: C# uses short-circuit logic: in A && B, if A is false then B is not evaluated (useful for safe null checks).

if / else / else-if (Readable Branching)

Use if when there is a condition-based decision. Use else if to test another condition when the first is false, and else as the default fallback. The goal is readability: each branch should clearly explain “why” it exists. If branching gets long, consider refactoring (like switch or separate methods) to keep code clean. 

if / else-if / else flow
  if (cond1) -> block1
  else if (cond2) -> block2
  else -> block3 (default)
Example: Shipping cost based on distance

Distance <= 5 → ₹40, <= 20 → ₹80, else → ₹150

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int distanceKm = 12;
        int cost;

        if (distanceKm <= 5) cost = 40;
        else if (distanceKm <= 20) cost = 80;
        else cost = 150;

        Console.WriteLine("Shipping cost: ₹" + cost);
    }
}
Tip: Put the most common cases first only if it improves readability; otherwise keep conditions ordered logically.
Advanced note: Avoid repeating calculations in multiple branches; compute once and reuse to reduce bugs.

Nested if (When It’s OK + When to Refactor)

Nested if means an if inside another if. It’s OK when the logic is truly hierarchical (first check login, then check role). But deep nesting makes code hard to read and easy to break. A common refactor is to use early returns (in methods), combine conditions, or move logic into helper methods. 

Nested if (hierarchy)
if (loggedIn)
{
   if (isAdmin) -> show admin panel
   else -> show user panel
}
else -> ask login
Example: Access control (real-world)

If logged in, then check admin role; otherwise block access.

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        bool loggedIn = true;
        bool isAdmin = false;

        if (loggedIn)
        {
            if (isAdmin)
                Console.WriteLine("Welcome Admin: show dashboard");
            else
                Console.WriteLine("Welcome User: show profile");
        }
        else
        {
            Console.WriteLine("Please login first");
        }
    }
}
Tip: If nesting goes beyond 2 levels, pause and consider simplifying.
Advanced note: Prefer guard clauses in methods (early return) to flatten nesting; it improves maintainability and testability.

switch-case (Modern Patterns + Fallthrough Safety)

Use switch when one value can match many discrete cases (like menu selection or status codes). It can be more readable than long else-if chains. In C#, switch cases do not “fall through” by default—you typically end each case with break. Modern C# also supports switch expressions for concise, safe branching. 

switch mental model
  value -> match case -> execute block -> break
                |
             default (no match)
Example: Menu selection (real-world)

1=Add, 2=Subtract, 3=Exit. Anything else → Invalid.

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int choice = 2;

        switch (choice)
        {
            case 1:
                Console.WriteLine("Add selected");
                break;
            case 2:
                Console.WriteLine("Subtract selected");
                break;
            case 3:
                Console.WriteLine("Exit selected");
                break;
            default:
                Console.WriteLine("Invalid choice");
                break;
        }
    }
}
Tip: Use switch when decisions depend on a single variable (choice, status, type).
Advanced note: Switch expressions can reduce code size and errors, especially when every case returns a value.

Practice: Height Category + Largest of Three (Thinking Steps)

Practice is where control flow becomes natural. First: categorize height into labels (Short/Medium/Tall) using ordered conditions. Second: find the largest of three numbers using comparisons. Focus on thinking steps: write conditions, test sample inputs, and verify branch selection. 

Thinking steps
1) Read input(s)
2) Decide conditions (ordered!)
3) Execute exactly one correct branch
4) Print result
5) Test edge cases
Example: Height Category (cm)

<150 = Short, 150–169 = Medium, ≥170 = Tall

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int height = 165;

        if (height < 150) Console.WriteLine("Short");
        else if (height < 170) Console.WriteLine("Medium");
        else Console.WriteLine("Tall");

        int a = 10, b = 25, c = 18;
        int largest = a;

        if (b > largest) largest = b;
        if (c > largest) largest = c;

        Console.WriteLine("Largest: " + largest);
    }
}
Tip: Always order ranges correctly. If you check “<170” first, “<150” will never run.
Advanced note: For larger comparisons, consider using arrays + loops, or built-in methods (later) to simplify logic.

Loops Overview (while vs do-while vs for)

Loops repeat a block of code until a condition changes. Use while when you don’t know how many times you’ll repeat (keep asking until valid). Use do-while when you must run at least once (show menu at least once). Use for when you know the range/count (repeat 10 times, iterate through indices). 

Choose the loop
  while     -> repeat while condition is true (0 or more times)
  do-while  -> run once, then repeat while true (1 or more times)
  for       -> controlled counting loop (known iterations)
Example: Real-world loop selection

ATM PIN retries → while, menu display → do-while, print 1..N → for

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        // for: known count
        for (int i = 1; i <= 3; i++)
            Console.WriteLine("Attempt " + i);

        // while: unknown count (conceptual)
        int x = 0;
        while (x < 2)
        {
            Console.WriteLine("x = " + x);
            x++;
        }
    }
}
Tip: Infinite loops happen when the loop condition never becomes false—always ensure progress (increment/change state).
Advanced note: Many “repeat until valid” problems combine TryParse + while loop for robust input handling.

while and do-while (Input Validation & Menu Programs)

while and do-while are perfect for repeated prompts and menu programs. Use while when you want to validate before running the loop body. Use do-while to show the menu once, then repeat until user exits. This pattern is used in real apps for login retries, form validation, and console menus. 

do-while menu pattern
do
{
  show menu
  read choice
  run action
}
while (choice != exit)
Example: Menu program (console)

Keep running until user chooses 3 (Exit).

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int choice;

        do
        {
            Console.WriteLine("1) Say Hi  2) Show Time  3) Exit");
            Console.Write("Choice: ");
            int.TryParse(Console.ReadLine(), out choice);

            switch (choice)
            {
                case 1:
                    Console.WriteLine("Hi!");
                    break;
                case 2:
                    Console.WriteLine("Time: " + DateTime.Now.ToShortTimeString());
                    break;
                case 3:
                    Console.WriteLine("Goodbye!");
                    break;
                default:
                    Console.WriteLine("Invalid choice");
                    break;
            }
        }
        while (choice != 3);
    }
}
Tip: Use TryParse inside loops so invalid input doesn’t crash your program.
Advanced note: In larger apps, menu actions are often moved into methods to reduce switch complexity.

for Loop (Counting, Ranges, Iterations)

A for loop is best when you know the number of iterations. It has three parts: initialization, condition, and increment. Typical uses: counting, generating tables, iterating index-based arrays. A well-written for loop is easy to debug because the counter tells you exactly where you are. 

for (init; condition; increment)
{
   body
}

Example:
for (int i=1; i<=5; i++) print i
Example: Print a multiplication table

Print 7 × 1..10

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int n = 7;
        for (int i = 1; i <= 10; i++)
        {
            Console.WriteLine(n + " x " + i + " = " + (n * i));
        }
    }
}
Tip: If you see off-by-one errors, check your loop bounds (<= vs <).
Advanced note: Use meaningful loop variable names when loops represent concepts (day, index, attempt), not just i/j.

break / continue / nested loops / goto (Use Wisely)

break exits the nearest loop immediately, and continue skips to the next iteration. Nested loops are common in grids, tables, and searching combinations. goto exists but is usually avoided because it can make flow hard to follow. Use these tools carefully to keep control flow understandable and safe. 

Loop controls
  break     -> exit loop now
  continue  -> skip rest of this iteration
  nested loop -> loop inside loop (rows x cols)
  goto      -> jump label (avoid unless necessary)
Example: Find first even number in a list

Stop searching as soon as you find the first match (break).

Try It Yourself 
using System;

class Program
{
    static void Main()
    {
        int[] nums = { 3, 7, 9, 10, 11 };

        for (int i = 0; i < nums.Length; i++)
        {
            if (nums[i] % 2 != 0)
                continue; // skip odd numbers

            Console.WriteLine("First even: " + nums[i]);
            break; // stop after first even
        }
    }
}
Tip: Prefer break/continue over complex flags. But if you use many breaks, consider refactoring into methods.
Advanced note: For nested loops, you can use helper methods (return) or structured logic to exit cleanly without goto.

FAQs
When should I use switch instead of else-if?

Use switch when decisions depend on one variable with many discrete values (menu choice, status code). Else-if is better for range checks (like score bands).

Why do I get infinite loops?

Your loop condition never becomes false. Ensure the state changes each iteration (increment counters, read new input, update flags).

Should I use goto?

Usually no. It can make code harder to understand. Prefer methods + early return, or loop controls (break/continue) where possible.
