Structs vs Classes (Value Type vs Reference Type)

A struct is a Value Type: assigning it copies the whole value. A class is a Reference Type: assigning it copies only the reference. Choose structs for tiny “data packets” (like coordinates) and classes for complex entities (like Customer) with identity and behavior. 

Value Copy vs Reference Copy
----------------------------
struct (Value Type):             class (Reference Type):
a = b copies ALL fields          a = b copies ONLY reference
a changes do NOT affect b        a changes affect b (same object)
Example (When copy matters)
Imagine a Point struct for pixels: you want fast copies and no shared mutation. For a Customer class: you want one shared identity across the app. 
// C# example: struct copies, class shares reference
public struct Point2D
{
    public int X { get; set; }
    public int Y { get; set; }
}

public class Customer
{
    public string Name { get; set; } = "";
}

var p1 = new Point2D { X = 10, Y = 20 };
var p2 = p1;              // copy of values
p2.X = 99;                // p1.X remains 10

var c1 = new Customer { Name = "Asha" };
var c2 = c1;              // copy of reference
c2.Name = "Asha (VIP)";   // c1.Name also changes
Real-world use case: In a gaming app, positions/velocities can be structs (small and frequently copied), while Player/Inventory are classes (shared identity, rich relationships).
Beginner tip: If your type is small (few fields) and logically “a value”, start with a struct.
Advanced note: Avoid large structs; copying big values repeatedly can be slower than class references and can increase CPU cache pressure.

System.Object & Overriding (ToString, Equals, GetHashCode)

In C#, every type ultimately derives from System.Object. Overriding ToString improves logging, while Equals and GetHashCode must be consistent. If you define custom equality, you enable correct behavior in Dictionary/HashSet and avoid subtle bugs. 

Equality Flow
-------------
Equals()  -> "Are these two instances logically equal?"
GetHashCode() -> "Which bucket should it go into?"
Rule: If A.Equals(B) == true, then A.GetHashCode() MUST == B.GetHashCode()
Example (Customer identity)
If your system treats Email as unique identity, equality should compare Email (case-insensitive) rather than Name. 
public class Customer
{
    public string Email { get; }
    public string Name { get; }

    public Customer(string email, string name)
    {
        Email = email;
        Name = name;
    }

    public override string ToString() => $"Customer(Name={Name}, Email={Email})";

    public override bool Equals(object? obj)
    {
        if (obj is not Customer other) return false;
        return string.Equals(Email, other.Email, StringComparison.OrdinalIgnoreCase);
    }

    public override int GetHashCode()
        => StringComparer.OrdinalIgnoreCase.GetHashCode(Email);
}
Real-world use case: In an e-commerce app, you store customers in a HashSet to prevent duplicates. Correct overrides ensure “same email” doesn’t get inserted twice.
Beginner tip: If you override Equals, always override GetHashCode too.
Advanced note: For many “data-only” types, consider Record to get structural equality safely.

Boxing & Unboxing (Hidden Costs)

Boxing happens when a value type (like int) is treated as object, typically causing a heap allocation and copy. Unboxing extracts the value back and can fail if types mismatch. Hidden boxing often appears with non-generic collections, string formatting, or APIs that take object. Avoid it by using generics (List<int>), and by staying in strongly typed pipelines. 

Hidden Cost Snapshot
--------------------
Value type (int) --(boxing)--> object (heap allocation)
object --(unboxing)--> int (type check + copy)
Example (Non-generic collection traps)
ArrayList stores everything as object, so ints get boxed. Prefer List<int>. 
using System.Collections;

var arr = new ArrayList();
for (int i = 0; i < 3; i++)
{
    arr.Add(i); // BOXING each int into object
}

int first = (int)arr[0];  // UNBOXING back to int

// Better:
var list = new List<int>();
list.Add(0);              // no boxing
Real-world use case: In a logging pipeline processing millions of records, accidental boxing can create many allocations and increase GC pressure, slowing the service.
Beginner tip: If you see ArrayList or object-based APIs, double-check for boxing.
Advanced note: Boxing can also occur with interface calls on structs. Be careful when structs implement interfaces and are used via interface-typed variables.

Generics (Classes, Methods) + Constraints

Generics let you write reusable code without losing type safety. Instead of storing “object” and casting later, you keep everything strongly typed. Constraints tell the compiler what T is allowed to be, enabling safe features like calling new(), accessing base members, or requiring interfaces. 

Generic Design
--------------
Without generics: store object + cast later (risk)
With generics:    store T + compile-time safety (safe)
Example (Repository with constraints)
If you require an Id, constrain T to an interface like IEntity. 
public interface IEntity
{
    int Id { get; }
}

public class Repository<T> where T : class, IEntity, new()
{
    private readonly Dictionary<int, T> _store = new();

    public T Add(int id)
    {
        var entity = new T(); // allowed because of new() constraint
        _store[id] = entity;
        return entity;
    }

    public bool TryGet(int id, out T? entity) => _store.TryGetValue(id, out entity);
}
Real-world use case: A shared library for many microservices can provide generic validation, caching, mapping, and repositories that work across entity types.
Beginner tip: Prefer List<T>, Dictionary<TKey,TValue> over object-based containers.
Advanced note: Use constraints to reduce runtime checks and make your API self-documenting (the compiler enforces the rules).

Nullable Types + Null Operators (??, ?., ??=)

A Nullable value type (like int?) can represent “no value”. Null operators make code safer and shorter: Null Coalescing (??) provides defaults, Null Propagation (?.) safely chains access, and ??= assigns only when null. 

Null Safety Flow
----------------
value?.Member   -> if value is null, result is null (no crash)
value ?? backup -> if value is null, use backup
value ??= x     -> assign x only if value is null
Example (Config fallback)
If a setting is missing, default to a safe value and continue smoothly. 
string? regionFromEnv = Environment.GetEnvironmentVariable("APP_REGION");

// fallback
string region = regionFromEnv ?? "ap-south-1";

// safe chain
int? len = regionFromEnv?.Length;

// assign default only if null
regionFromEnv ??= "unknown";
Real-world use case: In API services, incoming JSON can omit optional fields. Nullable types + null operators prevent crashes and simplify validation logic.
Beginner tip: Use TryParse-style patterns for user input, and keep optional fields nullable.
Advanced note: Combine null operators with guard clauses to keep methods short and readable (fail fast, then proceed confidently).

Extension Methods (Add Methods Without Modifying Types)

Extension Methods let you “add” methods to existing types without inheritance or modifying source code. They are static methods in a static class, where the first parameter uses the this keyword. This enables clean fluent APIs, and is perfect for shared utility functions like validation and formatting. 

How it Feels
------------
Before: Utils.IsValidEmail(email)
After:  email.IsValidEmail()   (same static call, nicer syntax)
Example (Email validation helper)
Keep validation logic centralized, but call it naturally on string values. 
public static class StringExtensions
{
    public static bool IsValidEmail(this string? value)
    {
        if (string.IsNullOrWhiteSpace(value)) return false;
        return value.Contains("@") && value.Contains(".");
    }
}

string email = "asha@company.com";
bool ok = email.IsValidEmail();
Real-world use case: In a large codebase, extension methods standardize common operations (normalizing phone numbers, trimming inputs, formatting currency) across teams.
Beginner tip: Keep extension methods small and focused; avoid hiding complex business rules inside them.
Advanced note: Prefer domain services for behavior that depends on infrastructure (DB, network). Extension methods should be “pure” helpers.

Pattern Matching (is, switch patterns)

Pattern Matching makes type checks and condition checks readable and safe. With is, you can both test and capture a typed variable. With switch patterns, you can handle multiple shapes of data cleanly (types, property patterns, guards). This is especially useful when processing mixed message types or API responses. 

Pattern Matching Flow
---------------------
input object
  |
  +-- is TypeA a  -> handle A
  +-- is TypeB b  -> handle B
  +-- null        -> safe fallback
Example (Payment method routing)
Different payment methods are handled differently without messy casts. 
public interface IPayment { }
public class CardPayment : IPayment { public decimal Amount { get; set; } }
public class UpiPayment  : IPayment { public decimal Amount { get; set; } }

static string RoutePayment(IPayment? payment) => payment switch
{
    CardPayment c when c.Amount > 0 => "Route: Card Gateway",
    UpiPayment u  when u.Amount > 0 => "Route: UPI Switch",
    null => "No payment provided",
    _ => "Unsupported payment"
};
Real-world use case: In an event-driven system, a consumer receives different event types. Pattern matching allows clean routing logic with safer code.
Beginner tip: Use “is Type x” to avoid writing separate cast lines.
Advanced note: Property patterns and “when” guards can replace many nested validations while keeping logic in one place.

Arrays Deep Dive (Multi-Dimensional & Jagged) + System.Array

Arrays are fixed-size containers; they are reference types even when holding value types. Multi-dimensional arrays (like int[,]) are “grid-like”, while jagged arrays (int[][]) are arrays of arrays. Use multi-dimensional arrays for true matrix shapes, and jagged arrays when each row can have different length. The System.Array API provides helpers like Sort, Reverse, and Copy. 

Array Shapes
------------
Multi-dimensional: int[,] grid (rows x cols, rectangular)
Jagged:           int[][] rows (each row can vary in length)
Example (Matrix vs variable rows)
Exam seating in fixed classroom grid fits int[,]. Monthly sales where each month has different days fits int[][]. 
// Multi-dimensional (rectangular)
int[,] grid = new int[2,3] { {1,2,3}, {4,5,6} };

// Jagged (rows can differ)
int[][] jag = new int[2][];
jag[0] = new int[] { 10, 20 };
jag[1] = new int[] { 30, 40, 50 };

// System.Array utilities
int[] scores = { 60, 20, 90, 40 };
Array.Sort(scores);
Array.Reverse(scores);
Real-world use case: Image processing often uses a fixed grid (multi-dimensional), while log batches may vary in size (jagged).
Beginner tip: Start with List<T> unless you truly need fixed size and maximum performance.
Advanced note: Jagged arrays can be more cache-friendly for some variable-length workloads, but require careful null/length checks.

Collections Overview (List, Dictionary, HashSet, Stack, Queue, etc.)

Collections store multiple items, but each collection is optimized for different operations. List is great for ordered data, Dictionary is best for key-based lookup, and HashSet enforces uniqueness. Use Stack/Queue for LIFO/FIFO workflows, like undo/redo or job processing. 

Pick the Right Tool
-------------------
Need order + indexing?      List
Need key lookup?            Dictionary
Need uniqueness?            HashSet
Need FIFO jobs?             Queue
Need LIFO undo?             Stack
Example (Orders and quick lookups)
Store orders in a list (display), and build a dictionary for fast “OrderId → Order” lookup. 
var orders = new List<string> { "ORD1001", "ORD1002", "ORD1003" };

var orderIndex = new Dictionary<string, string>();
foreach (var id in orders) orderIndex[id] = id;

bool exists = orderIndex.ContainsKey("ORD1002");

var uniqueCities = new HashSet<string> { "Chennai", "Jaipur", "Chennai" }; // duplicates removed

var jobs = new Queue<string>();
jobs.Enqueue("SendEmail");
jobs.Enqueue("GenerateInvoice");
string nextJob = jobs.Dequeue();
Real-world use case: In a booking system, you maintain unique room numbers (HashSet), a queue of housekeeping tasks (Queue), and a dictionary cache of roomId → roomDetails (Dictionary).
Beginner tip: If unsure, start with List<T>, then switch when performance needs appear.
Advanced note: Big-O matters, but real performance also depends on allocations, hashing quality, and data size patterns.

Custom Collections (IEnumerable, IEnumerator, IComparable, IComparer)

Custom collections become powerful when they support foreach iteration and sorting. Implementing IEnumerable enables iteration, while IEnumerator is the engine behind it. For sorting, IComparable defines “natural” order, and IComparer provides alternate strategies. 

Iteration Model
---------------
Collection (IEnumerable)
  |
  +-- GetEnumerator() -> Enumerator (IEnumerator)
        |
        +-- MoveNext() / Current / Reset()
Example (Iterable custom range + sortable product)
Build a custom Range that can be iterated; build Product sorting by default or by price using IComparer. 
public class SimpleRange : IEnumerable<int>
{
    private readonly int _start, _end;

    public SimpleRange(int start, int end)
    {
        _start = start;
        _end = end;
    }

    public IEnumerator<int> GetEnumerator()
    {
        for (int i = _start; i <= _end; i++)
            yield return i; // compiler creates IEnumerator
    }

    System.Collections.IEnumerator System.Collections.IEnumerable.GetEnumerator()
        => GetEnumerator();
}

public class Product : IComparable<Product>
{
    public string Name { get; set; } = "";
    public decimal Price { get; set; }

    public int CompareTo(Product? other)
    {
        if (other is null) return 1;
        return string.Compare(Name, other.Name, StringComparison.OrdinalIgnoreCase);
    }
}

public class PriceComparer : IComparer<Product>
{
    public int Compare(Product? x, Product? y)
        => (x?.Price ?? 0).CompareTo(y?.Price ?? 0);
}
Real-world use case: A reporting library exposes custom time ranges (iterable) and allows sorting reports by name, date, or total using different comparers.
Beginner tip: Use “yield return” to implement IEnumerable quickly and clearly.
Advanced note: Iterator blocks create state machines; for ultra-hot paths, you may optimize to avoid extra allocations.

Anonymous Types, Tuples & Deconstruction

Anonymous types are quick, local “shapes” for temporary projections (often used with LINQ). Tuples provide lightweight multiple return values without creating a full class. Deconstruction lets you pull tuple (or custom type) parts into variables in one readable line. Use them for small transformations, but prefer named types for public APIs and long-term models. 

Data Shapes
-----------
Anonymous Type: new { Name = ..., Total = ... }  (local only)
Tuple: (int Id, string Name)                    (lightweight return)
Deconstruction: var (id, name) = tuple;
Example (Returning two values cleanly)
Return (isValid, message) from validation without out parameters. 
static (bool ok, string message) ValidateAge(int age)
{
    if (age < 18) return (false, "Must be 18+");
    return (true, "OK");
}

var result = ValidateAge(20);
var (ok, msg) = result;  // deconstruction

var reportRow = new { Name = "Ravi", Total = 1250m }; // anonymous type
Real-world use case: In data pipelines, you project only what you need (anonymous types), return multi-values from helpers (tuples), and keep code readable with deconstruction.
Beginner tip: Use tuples for internal helpers; don’t expose them everywhere in public libraries.
Advanced note: Prefer clear domain models (classes/records) for boundaries: API contracts, storage models, and shared packages.

LINQ Basics + Aggregates (Select, OrderBy, Min/Max/Sum/Avg)

LINQ lets you build pipelines: filter, transform, sort, and aggregate. Most LINQ methods work on IEnumerable so they work across lists, arrays, and custom iterators. Aggregates like Min/Max/Sum/Avg give quick insights. A key idea: many operations are deferred until you enumerate (foreach, ToList, Count). 

LINQ Pipeline
-------------
source --Where--> filtered --Select--> projected --OrderBy--> sorted --Aggregate--> result
Example (Sales analytics in memory)
Find top sales, average order, and build a simplified view for UI. 
public record Order(string Id, decimal Total);

var orders = new List<Order>
{
    new("ORD1", 1200m),
    new("ORD2", 250m),
    new("ORD3", 750m),
    new("ORD4", 1500m)
};

var bigOrders = orders
    .Where(o => o.Total >= 700m)
    .Select(o => new { o.Id, o.Total })
    .OrderByDescending(x => x.Total)
    .ToList();

decimal max = orders.Max(o => o.Total);
decimal avg = orders.Average(o => o.Total);
decimal sum = orders.Sum(o => o.Total);
Real-world use case: In dashboards, you often load data from DB once and use LINQ to create multiple filtered views without rewriting loops everywhere.
Beginner tip: If a LINQ chain feels confusing, rewrite it as a foreach once, then convert back.
Advanced note: Be careful with multiple enumerations; store results with ToList() when you will reuse a query many times.

Core BCL APIs (StringBuilder, DateTime, Math)

The BCL gives battle-tested tools for daily work. Use StringBuilder for heavy string building, DateTime for time operations, and Math for numeric calculations. These APIs keep code concise and fast when used correctly. 

When to use StringBuilder
-------------------------
Many concatenations in a loop?  Use StringBuilder
A few concatenations?          Normal string is fine
Example (Report line generation)
Build a multi-line report efficiently and stamp it with a generated time. 
using System.Text;

var sb = new StringBuilder();
sb.AppendLine("Daily Sales Report");
sb.AppendLine("------------------");

for (int i = 1; i <= 3; i++)
{
    sb.AppendLine($"Item {i}: ₹{Math.Round(i * 123.45, 2)}");
}

string report = sb.ToString();
DateTime createdAt = DateTime.Now;
Real-world use case: Generating invoices, CSV exports, or log summaries often needs efficient string building and accurate timestamps.
Beginner tip: For time differences, use TimeSpan (e.g., end - start) rather than manual math.
Advanced note: In distributed systems, prefer UTC timestamps to avoid timezone surprises and DST issues.

IO, Serialization & Encoding (Files + JSON/XML)

IO is how your program reads/writes data to files, streams, and storage. Serialization converts objects into JSON/XML for APIs and storage. Encoding controls how text becomes bytes; UTF-8 is a common safe default. Use try/catch for IO failures (missing file, locked file), and validate inputs before writing. 

IO + Serialization Flow
-----------------------
Object --Serialize--> JSON string --Encode--> bytes --Write--> file
File --Read--> bytes --Decode--> JSON string --Deserialize--> Object
Example (Save settings to JSON)
Store app configuration in a file so it can be edited or deployed with the application. 
using System.Text;
using System.Text.Json;

public record AppSettings(string Region, int RetryCount);

var settings = new AppSettings("ap-south-1", 3);

// Serialize to JSON
string json = JsonSerializer.Serialize(settings, new JsonSerializerOptions { WriteIndented = true });

// Write to file with explicit UTF-8
File.WriteAllText("appsettings.local.json", json, Encoding.UTF8);

// Read back
string readJson = File.ReadAllText("appsettings.local.json", Encoding.UTF8);
var loaded = JsonSerializer.Deserialize<AppSettings>(readJson);
Real-world use case: Microservices often store local settings for dev/test, export JSON payloads for audit, or generate XML for legacy systems.
Beginner tip: Always use WriteIndented for config files to keep them readable for humans.
Advanced note: For large files, prefer streams (FileStream + async) instead of reading everything into memory at once.

Exception Handling + Modern C# (Records, Top-Level, File-Scoped)

Exception handling prevents your program from crashing and helps you produce clear error messages. Use try/catch/finally around risky operations (IO, parsing, network). Modern C# features like Top-Level Statements, File-Scoped Namespace, and Record improve productivity and correctness. 

Error Handling Flow
-------------------
try { risky work }
catch (specific) { handle + log }
catch (general)  { fallback }
finally { cleanup }
Example (Safe file read + parsing)
Handle missing file and invalid numbers without crashing, and return a meaningful result. 
// Example shows try/catch and a record DTO
public record ImportResult(bool Ok, string Message, int Count);

static ImportResult ImportNumbers(string path)
{
    try
    {
        if (!File.Exists(path))
            return new ImportResult(false, "File not found", 0);

        string[] lines = File.ReadAllLines(path);
        int count = 0;

        foreach (var line in lines)
        {
            if (int.TryParse(line, out _)) count++;
        }

        return new ImportResult(true, "Import complete", count);
    }
    catch (UnauthorizedAccessException)
    {
        return new ImportResult(false, "No permission to access file", 0);
    }
    catch (Exception)
    {
        return new ImportResult(false, "Unexpected error during import", 0);
    }
}
Real-world use case: Importing CSV/JSON into a system must survive bad inputs and missing files, returning clear errors for support teams and users.
Beginner tip: Catch specific exceptions first (like UnauthorizedAccessException), then general ones last.
Advanced note: Prefer returning domain-friendly error results at boundaries, and log technical details internally for debugging.

FAQs

1) When should I choose struct over class?

Answer: Use struct for small, immutable, “value-like” data (e.g., Point, Money) where copying is expected. Use class for entities with identity and shared references.

2) Why does overriding Equals require GetHashCode?

Answer: Hash-based collections rely on GetHashCode to find buckets; if equal objects have different hashes, lookups fail or behave inconsistently.

3) Is LINQ always slower than loops?

Answer: Not always. LINQ is readable and often “fast enough”, but hot paths may benefit from loops. Measure when performance truly matters.

4) Should I store dates as local time or UTC?

Answer: Store UTC and convert to local for display. This avoids timezone and daylight-saving problems.

  • Choose struct for small value-like data; choose class for identity and shared references.
  • Override Object methods carefully; equality must match hash codes for correct collection behavior.
  • Avoid hidden boxing by using generic collections and type-safe APIs.

ConstraintsRules on generic type parameters (where T : class/new()/BaseType). Lets compiler allow safe operations on T. Prevents invalid usage.
NullableFeature for representing missing values. int? can store null as well as an int. Helps avoid magic numbers like -1.
Null CoalescingReturns fallback value if left side is null. Common for defaults and configuration. Reduces if-null checks.
Null PropagationStops member access if left side is null. Prevents NullReferenceException in chains. Returns null instead of crashing.
Extension MethodsStatic methods that appear like instance methods. Extend existing types without editing them. Used heavily by LINQ for fluent chains.
Pattern MatchingModern way to check types and conditions. Uses is/switch patterns for clarity. Reduces nested if statements.
LINQLanguage Integrated Query for data operations. Creates readable pipelines using method syntax. Works on IEnumerable sequences.
IEnumerableInterface that supports iteration with foreach. Foundation for streaming sequences. Used by most LINQ methods.
SerializationConverting objects to formats like JSON or XML. Used for APIs, caching, configs. Allows data transfer between systems.
EncodingMaps characters to bytes (UTF-8, UTF-16). Wrong encoding corrupts text. Always set encoding intentionally for files.
RecordC# data-focused type with value-like equality. Ideal for DTOs and immutable models. Reduces boilerplate code.
Top-Level StatementsC# programs can be written without explicit Main. Great for learning and quick demos. Compiles as normal under the hood.
File-Scoped NamespaceApplies namespace to entire file without braces. Reduces indentation and clutter. Improves readability in big projects.
StringBuilderEfficiently builds strings without many allocations. Ideal for loops and large concatenations. Avoids repeated string copies.
DateTimeRepresents date and time values. Used for timestamps, scheduling, and durations. Combine with TimeSpan for differences.
