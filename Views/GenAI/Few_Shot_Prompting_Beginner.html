1) What is Few-Shot?

Few-shot prompting means you show the model a small set of examples of the task (inputs with correct outputs) before asking it to solve a new, similar case.

Think of it as: “Here are 2–5 solved samples. Now solve this new one in the same way.”

2) Building Blocks (Simple Definitions)

Instruction: The main command for the task. Example: "Classify reviews by sentiment."

Example (shot): A pair of Input and Output that demonstrates the correct style/format.

Demonstration set: The small collection of examples you include (usually 2–5).

Constraints: Rules the model must follow (labels, word limits, “JSON only”, etc.).

Output format: The exact layout for the answer (often JSON).

New input (query): The fresh case the model must solve after seeing the examples.

3) A Simple Recipe

  1. Write a short instruction for the task.
  2. Add 2–5 small, varied examples (each with input and correct output).
  3. State constraints and output format.
  4. Provide the new input to solve.
  5. (Optional) Add acceptance checks or a role if needed.

4) Prompt Patterns

Pattern A — Labeled Examples + New Query
Instruction: Classify the sentiment as "positive", "negative", or "neutral". Return JSON only.

Examples:
Input: "The battery lasts all day." 
Output: {"label":"positive"}

Input: "The camera is blurry and overheats." 
Output: {"label":"negative"}

Input: "It works okay for now." 
Output: {"label":"neutral"}

New Input:
"Delivery was late, but the product quality is excellent."
Pattern B — Extraction with JSON Schema
Instruction: Extract {"invoice_no":string, "amount_in_inr":number, "date":"YYYY-MM-DD"|null}. Return JSON only.

Examples:
Text: "Invoice INV-77 for ₹1250 was paid on 5 Jan 2025." 
Output: {"invoice_no":"INV-77","amount_in_inr":1250,"date":"2025-01-05"}

Text: "Paid ₹900, invoice X-9. No date mentioned." 
Output: {"invoice_no":"X-9","amount_in_inr":900,"date":null}

New Text:
"Please process payment of ₹1,499 for invoice AB-12, meeting on 14 Aug 2024."
Pattern C — Style Transfer (Few Shots)
Instruction: Rewrite to a polite, professional tone in ≤20 words. Return only the rewritten sentence.

Examples:
Original: "Send the file now."
Rewritten: "Please share the file as soon as possible."

Original: "You missed the deadline."
Rewritten: "Could you share an update on the deadline when you can?"

New Text:
"Why is this still pending?"

5) Fully Worked Examples

Needs Improvement (Why it is weak)
"Classify reviews. Here are many examples..." (100+ lines)
  • Too many examples can exhaust context and add noise.
  • Examples don’t show all labels or edge cases.
  • No fixed output format (hard to check results).
Good Prompt (Clear, Balanced, Teaches the Pattern)
Instruction: Classify as "positive", "negative", or "neutral". Return JSON only.

Examples:
Input: "Works like a charm." 
Output: {"label":"positive"}

Input: "It keeps crashing." 
Output: {"label":"negative"}

Input: "It's fine." 
Output: {"label":"neutral"}

New Input: "Good value, but the charger heats up."
Why it is good: covers each label, keeps examples short, enforces JSON.
Example — Extraction with Units
Instruction: Extract {"name":string,"amount_in_inr":number,"date":"YYYY-MM-DD"|null}. Return JSON only.

Examples:
Text: "Paid ₹1,250 to Priya on 02-01-2025." 
Output: {"name":"Priya","amount_in_inr":1250,"date":"2025-01-02"}

Text: "Sent 2000 INR to Amit, will confirm date later." 
Output: {"name":"Amit","amount_in_inr":2000,"date":null}

New Text:
"Transferred ₹3,150 to Ravi today (14 Aug 2024) for travel."
Expected Output
{"name":"Ravi","amount_in_inr":3150,"date":"2024-08-14"}

6) Do / Don’t (with reasons)

DoDon’tReason
Use 2–5 short, diverse examples. Use very long or many examples. Short examples save space and teach the pattern clearly.
Cover every label or field at least once. Show only the easy or positive cases. Balanced examples reduce bias and mistakes.
Fix the output format (e.g., JSON). Allow free-form answers when structure matters. Structure makes results checkable and automatable.
Place examples before the new input. Put examples after the new input. Order helps the model copy the demonstrated pattern.
Add edge cases (nulls, mixed signals). Avoid tricky cases. Edge cases prevent surprises later.

7) Practice Tasks

  1. Classification: Create a few-shot prompt to label support tickets {"P1","P2","P3"} with JSON output only.
  2. Extraction: Create a few-shot prompt to extract {"customer","order_id","amount_in_inr"} from chat logs. Show two examples with nulls.
  3. Rewrite: Create a few-shot prompt to make messages friendly in ≤20 words. Include two examples and a new text.

8) Glossary

  • Few-shot: Prompting with a handful of examples.
  • Shot: One example (input → output).
  • Demonstration set: The small collection of examples shown.
  • Generalization: The model applying the learned pattern to new inputs.
  • Edge case: A tricky or uncommon situation that often causes errors.

9) Summary

Few-shot prompting teaches by example. Use 2–5 short, varied samples that cover labels and edge cases, lock the output format, then present the new input. This simple structure improves accuracy and consistency.
