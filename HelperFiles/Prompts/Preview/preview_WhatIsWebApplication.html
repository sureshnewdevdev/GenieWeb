What is a Web Application?

A web application is software that runs on a web server and is accessed through a web browser.

Instead of installing an app on every device, you open a URL and use the app online (login, forms, dashboards, reports, payments, etc.).

Quick Definition

A web application is an application you use through a browser (Chrome/Edge/Firefox) where the main processing happens on a server. You interact using web pages (HTML/CSS/JavaScript) and the server returns results.

Real-life analogy:
Think of ATM vs UPI app:
  • Your phone/browser is like the “screen + buttons” (client)
  • The bank system does the real work (server)
  • The server validates, updates balances, and sends results back (response)

Why Web Applications Matter

  • Accessible anywhere: Works from any device with a browser.
  • Centralized updates: Update once on the server; all users get it immediately.
  • Multi-user support: Logins, roles, dashboards, workflows.
  • Integrations: Connect to databases, APIs, payments, email, analytics.
Warning: Web apps must handle security (authentication, authorization, input validation) because they are exposed over the internet.

Core Concept: Client–Server + Request–Response

Web applications work using a request and response cycle. The browser sends an HTTP request to a server. The server processes it and returns an HTTP response (HTML/JSON/files).

Diagram 1: Client–Server (concept flow)

+------------------+         HTTP Request          +----------------------+
| Client (Browser) | ----------------------------> | Server (Web App)     |
| HTML/CSS/JS UI   |                               | C# / Business Logic  |
+------------------+                               +----------------------+
          ^                                                 |
          |                 HTTP Response                    |
          +-------------------------------------------------+
                       (HTML / JSON / File)

Diagram 2: Real request/response flow (login example)

User opens: https://site.com/Account/Login

1) Browser sends GET /Account/Login
2) Server returns Login HTML page
3) User enters username/password and clicks Submit
4) Browser sends POST /Account/Login (form data)
5) Server validates user (DB/API), creates session/cookie
6) Server responds with Redirect to /Dashboard
7) Browser loads /Dashboard and shows user data

Tip: ASP.NET MVC is a framework used to build web applications in a structured way.

Step-by-Step: How a Web App Page is Served

  1. User types a URL in the browser (example: /Home/Index).
  2. Browser sends an HTTP request to the server (GET request).
  3. Server runs application code to prepare the result (data + HTML).
  4. Server returns the response (HTML page or JSON data).
  5. Browser renders HTML and loads CSS/JS for the UI.
Where ASP.NET MVC comes in: MVC helps you write step 3 (server processing) in a clean, maintainable structure.

Working Example: A Simple “Hello Web App” Page (MVC style)

Below is a minimal example showing how a web application returns HTML from the server using ASP.NET MVC. (You’ll learn full project creation in the next topics.)

1) Controller: Controllers/HomeController.cs

using System.Web.Mvc;

namespace MvcDemo.Controllers
{
    public class HomeController : Controller
    {
        // GET: /Home/Hello?name=Ajay
        public ActionResult Hello(string name)
        {
            name = string.IsNullOrWhiteSpace(name) ? "Guest" : name.Trim();
            ViewBag.Message = "Hello " + name + "! This page is served from a Web Application.";
            return View();
        }
    }
}

2) View: Views/Home/Hello.cshtml

@{
    ViewBag.Title = "Hello";
}

<h2>@ViewBag.Message</h2>

<div class="alert alert-light border">
    This content is generated by server code and returned as HTML to the browser.
</div>

<a class="btn btn-primary" href="/Home/Hello?name=Ravi">Try Another Name</a>

Common Mistakes + Fixes

Mistake Expecting the browser to execute C# code
Fix: C# runs on the server. The browser receives the final HTML/JS/CSS output.
Mistake Mixing database code inside HTML pages
Fix: Keep DB calls in services/repositories and pass results to views.
Mistake Not validating user inputs (security risk)
Fix: Validate inputs, use anti-forgery for forms, and apply proper authentication/authorization.

Mini Practice (Hands-on)

Task 1: Change the action name from Hello to Welcome and update the view name accordingly.
Expected Output: URL /Home/Welcome works and shows the same message.
Task 2: Add a second query parameter city and display: “Hello Ajay from Bengaluru”.
Expected Output: /Home/Hello?name=Ajay&city=Bengaluru shows full message.
Task 3: Create a new view that returns a simple table of 3 products (hard-coded list).
Expected Output: A page that renders an HTML table with Name and Price.

Q1. A web application is primarily accessed using:
A) Command Prompt
B) Web Browser
C) Notepad
D) BIOS
Answer: B) Web Browser
Web apps are designed to run on a server and be used through a browser via URLs. The browser is the client that renders pages and sends requests.
Q2. In a web app, C# code runs on:
A) Browser
B) Server
C) Router
D) Monitor
Answer: B) Server
Server-side languages (like C#) execute on the server. The browser receives the generated HTML/JS/CSS as the response.
Q3. The communication model of web apps is mainly:
A) Request–Response
B) Bluetooth pairing
C) USB transfer
D) Offline only
Answer: A) Request–Response
The browser sends HTTP requests, and the server returns HTTP responses. This is the core cycle behind loading pages, submitting forms, and fetching data.
Q4. Which is a common feature of web applications?
A) No internet usage
B) Centralized updates
C) Runs only on one PC
D) Cannot integrate with APIs
Answer: B) Centralized updates
Web apps are updated on the server side. Users get new features automatically when they refresh or reopen the site.
Q5. Which output does a server typically return for a web page?
A) HTML
B) Battery level
C) BIOS settings
D) USB drivers
Answer: A) HTML
For normal pages, the server returns HTML which the browser renders. For APIs, the response is often JSON.
Q6. Static websites usually:
A) Change per user using database
B) Have mostly fixed content
C) Always require login
D) Must use MVC
Answer: B) Have mostly fixed content
Static sites serve pre-built HTML files. Web apps typically generate content dynamically based on user actions and data.
Q7. Which is a good example of a web application?
A) Online banking portal
B) Plain brochure HTML page
C) Desktop calculator only
D) BIOS utility
Answer: A) Online banking portal
Banking portals involve login, transactions, role-based dashboards, and database updates. These are typical web application features.
Q8. Which protocol is commonly used by web apps?
A) HTTP/HTTPS
B) HDMI
C) VGA
D) SATA
Answer: A) HTTP/HTTPS
Web communication uses HTTP or HTTPS. HTTPS is preferred because it encrypts data between browser and server.
Q9. The browser is also called:
A) Server
B) Client
C) Compiler
D) Firewall
Answer: B) Client
In web apps, the browser is the client that requests content and displays it. The server hosts the application and returns responses.
Q10. Why are web apps easier to update than desktop apps?
A) No code is needed
B) Update once on server, everyone gets it
C) Users must reinstall daily
D) Browsers update your database automatically
Answer: B) Update once on server, everyone gets it
Since the app runs on the server, you deploy changes in one place. Users just refresh the site to use the latest version.

Interview Questions (10) + Answers

Click “Show Answer” to reveal each answer.

1) What is a web application?
A web application is software hosted on a web server and accessed via a browser. Users interact through web pages, and the server processes requests and returns responses (HTML/JSON).
2) What is the difference between a website and a web application?
A website often delivers mostly informational content, sometimes static. A web application is interactive and dynamic—users log in, submit data, trigger workflows, and data changes in a database.
3) What is HTTP request and response?
A request is sent by the client (browser) to ask for a page or data. A response is returned by the server containing HTML/JSON/files along with status codes like 200, 404, 500.
4) Why is HTTPS important for web apps?
HTTPS encrypts data between browser and server, protecting logins and sensitive data. It also improves trust and is a standard requirement for modern web apps and browsers.
5) What are typical components of a web application?
Client (browser UI), server application (business logic), database (persistent data), and integrations (APIs, email, payments). Monitoring/logging is also important in real deployments.
6) What is a “client” in a web app?
The client is the user-side application (usually a browser) that requests resources from a server. It renders HTML/CSS, runs JavaScript, and sends HTTP requests.
7) What is a “server” in a web app?
The server hosts the web application and executes server-side code (like C#). It handles requests, applies business rules, and returns responses to the client.
8) What is a session/cookie in web apps?
Cookies store small data in the browser (like auth tokens or session ids). Sessions store server-side user state mapped to that session id, commonly used after login.
9) How do web apps handle multiple users?
Web apps use authentication, sessions/tokens, and databases to track user identity and data. Authorization ensures each user can access only permitted pages and actions.
10) How does this topic connect to ASP.NET MVC?
ASP.NET MVC is a framework for building web applications on the server. It helps you handle requests (Controllers), manage data (Models), and render pages (Views) in a clean structure.

Summary + Next Steps

  • It works using HTTP request/response between client and server.
  • Web apps are dynamic, interactive, and often connected to databases/APIs.
