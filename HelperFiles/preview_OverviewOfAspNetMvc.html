Overview of ASP.NET MVC

ASP.NET MVC is a web framework for building structured, maintainable web applications using the Model–View–Controller pattern.

It separates request handling, UI rendering, and data/business rules—so your application stays clean even as it grows.

Quick Definition

ASP.NET MVC is a framework that helps you build web apps by organizing code into: Controller (handles requests), View (renders HTML), and Model (data + rules).

Real-life analogy:
Think of an online food delivery:
  • View = App screen showing menu and order details
  • Controller = Order coordinator that processes user clicks and decides next step
  • Model = Order data + pricing rules + validation

Why ASP.NET MVC Matters

  • Clean structure: UI, logic, and data don’t get mixed into one file.
  • Easy maintenance: Change UI without rewriting business logic (and vice versa).
  • Test-friendly: Controllers and services can be unit-tested.
  • Better collaboration: Frontend and backend work can happen in parallel.
  • Built-in web features: Routing, model binding, validation, filters, and layouts.
Warning: If you put heavy logic in Views, your app becomes hard to test and debug.

Core Concept: How ASP.NET MVC Works

The browser sends a request (URL). MVC uses Routing to select the correct Controller and Action. The action gets or updates data (Model/Service) and returns a View that renders HTML.

Step-by-Step: What you create in an MVC app

  1. Create a Controller to handle requests (ex: HomeController).
  2. Create an Action (method) to return a page (ex: Welcome()).
  3. Create a View under Views/{Controller}/{Action}.cshtml.
  4. (Optional) Create a Model class if the View needs structured data.
  5. Run and test with URLs like /Home/Welcome?name=Ajay.
Tip: Keep business logic in a Service/Repository class and keep controllers “thin”.

Working Example: Welcome Page (Controller → View → Output)

This mini example shows a complete MVC flow with a strongly typed model.

1) Model: Models/WelcomeVm.cs

namespace MvcDemo.Models
{
    public class WelcomeVm
    {
        public string Name { get; set; }
        public string Message { get; set; }
    }
}

2) Controller: Controllers/HomeController.cs

using System.Web.Mvc;
using MvcDemo.Models;

namespace MvcDemo.Controllers
{
    public class HomeController : Controller
    {
        // GET: /Home/Welcome?name=Ajay
        public ActionResult Welcome(string name)
        {
            name = string.IsNullOrWhiteSpace(name) ? "Guest" : name.Trim();

            var vm = new WelcomeVm
            {
                Name = name,
                Message = $"Welcome, {name}! You are viewing an ASP.NET MVC page."
            };

            return View(vm);
        }
    }
}

3) View: Views/Home/Welcome.cshtml

@model MvcDemo.Models.WelcomeVm
@{
    ViewBag.Title = "Welcome";
}

<h2>@Model.Message</h2>

<div class="alert alert-light border">
    <b>Name:</b> @Model.Name
</div>

<a class="btn btn-primary" href="/Home/Welcome?name=Gopi">Try Another</a>

Common Mistakes + Fixes

Mistake Placing database queries inside Views
Fix: Keep Views for UI only. Fetch data in Controller via Service/Repository and pass it as a Model.
Mistake Action method name doesn’t match view file
Fix: Ensure view is in Views/{ControllerName}/{ActionName}.cshtml.
Mistake Null reference in Razor when Model is missing
Fix: Validate inputs and always return a model; use 404 or error views when needed.

MCQ (10)

Q1. What does MVC stand for?
A) Model–View–Controller
B) Main–Value–Control
C) Multiple–View–Command
D) Model–Variable–Cloud
Answer: A) Model–View–Controller
MVC is a pattern that separates application data/rules (Model), UI rendering (View), and request handling (Controller) to build maintainable applications.
Q2. Which component decides which controller/action to execute based on the URL?
A) View
B) Routing
C) Model
D) CSS Bundle
Answer: B) Routing
Routing maps the incoming URL to Controller + Action + parameters. Example: /Home/Welcome maps to HomeController.Welcome().
Q3. Which layer should contain HTML + Razor markup?
A) Model
B) Controller
C) View
D) RouteConfig
Answer: C) View
Views render HTML. Controllers coordinate the workflow and Models represent data and rules. Keeping UI in Views avoids mixing logic into presentation.
Q4. The best return type for flexible MVC actions is usually:
A) ActionResult
B) SqlConnection
C) IList
D) HttpClient
Answer: A) ActionResult
ActionResult can represent a View, Redirect, JSON, File, or status code. This makes it a common choice for controller actions.
Q5. Why do we prefer strongly typed views?
A) They automatically create database tables
B) They provide compile-time checking and IntelliSense
C) They replace routing
D) They disable validation
Answer: B) They provide compile-time checking and IntelliSense
With @model, you get property suggestions and fewer runtime errors. It’s safer than using dynamic ViewBag values for primary data.
Q6. Where should business rules (price calculation, validation) ideally live?
A) View
B) Model/Service layer
C) RouteConfig
D) Layout page only
Answer: B) Model/Service layer
Business rules are reusable and testable when stored in services/models. Controllers should coordinate, and Views should display results.
Q7. Which is a correct MVC folder path for the Welcome view?
A) Views/Shared/Welcome.cshtml
B) Views/Home/Welcome.cshtml
C) Controllers/Home/Welcome.cshtml
D) Models/Home/Welcome.cshtml
Answer: B) Views/Home/Welcome.cshtml
Default convention: Views/{ControllerName}/{ActionName}.cshtml. Shared is typically used for layouts and reusable partial views.
Q8. What does model binding do in MVC?
A) Binds CSS to HTML
B) Converts request values into action parameters/models
C) Binds IIS to SQL Server
D) Binds scripts into bundles only
Answer: B) Converts request values into action parameters/models
MVC reads query string, route values, and form data to populate action parameters and objects. This reduces manual parsing code in controllers.
Q9. What is the role of _Layout.cshtml?
A) Stores database schema
B) Provides a shared master page structure for multiple views
C) Replaces controllers
D) Converts models to JSON
Answer: B) Provides a shared master page structure for multiple views
Layout defines common UI elements like header, navbar, sidebar, footer. Individual views inject their content into @RenderBody().
Q10. Which statement best describes a “thin controller”?
A) A controller with no actions
B) A controller that only contains UI markup
C) A controller that delegates logic to services and coordinates flow
D) A controller that stores data in ViewBag only
Answer: C) A controller that delegates logic to services and coordinates flow
Thin controllers receive input, call services/repositories, and return a result. Heavy business logic stays in service/domain classes for testing and reuse.

Interview Questions (10) + Answers

Click “Show Answer” to reveal each answer.

1) What is ASP.NET MVC?
ASP.NET MVC is a web framework that implements the MVC pattern. It provides routing, controllers, views (Razor), model binding, validation, and filters to build structured web apps.
2) Explain the request lifecycle in MVC.
Browser sends URL → routing selects controller/action → action executes → gets/updates data → returns view/result → Razor renders HTML → browser displays. This flow keeps responsibilities separated and predictable.
3) What is the difference between ViewBag and Model?
Model is the primary strongly typed object passed to the view (preferred). ViewBag is dynamic and used for small extra values. Model gives compile-time safety and IntelliSense.
4) What is model binding?
Model binding automatically maps request data (route, query string, form) to action parameters or model objects. It reduces manual parsing and makes actions cleaner.
5) Why use layouts in MVC?
Layouts provide a consistent UI structure across pages (header/nav/footer/sidebar). Views reuse the layout and inject page content into @RenderBody(), reducing duplication.
6) What is an ActionResult?
ActionResult is a flexible return type for actions. Actions can return ViewResult, JsonResult, RedirectResult, FileResult, or status codes depending on scenario.
7) What are partial views used for?
Partial views are reusable UI fragments (e.g., header blocks, product cards). They help avoid repeating Razor/HTML across multiple views and improve maintainability.
8) What is a ViewModel and why do you need it?
ViewModel is a UI-focused class that contains exactly what the view needs. It prevents over-exposing domain/database entities and keeps views strongly typed and clean.
9) How do you return a 404 in MVC?
Use return HttpNotFound(); or return HttpNotFound("message");. For friendly UI, route to a custom error view while still keeping correct status.
10) What makes an MVC app scalable in the long run?
Clear separation of concerns + layered design (Controller → Service → Repository). This reduces code duplication, improves testing, and makes feature changes safer.

  • Controllers should coordinate, and Views should focus on UI rendering.
